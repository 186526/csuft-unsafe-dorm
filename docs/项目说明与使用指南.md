# 项目说明与使用指南

本文档用于补充介绍 `csuft-unsafe-dorm` 项目的功能、使用方式、自动签到机制和日志位置。

说明：

- 不修改现有 `readme.md` 的原有内容。
- 本文档仅作为额外中文说明，方便直接查看。

## 1. 项目是做什么的

`csuft-unsafe-dorm` 是一个面向中南林业科技大学平安打卡场景的自动签到工具。

它目前既可以作为命令行脚本使用，也可以作为本地 Web 工具使用。项目支持：

- 使用 OpenID 进行身份认证
- 手动触发签到
- 多个 OpenID 账号连续签到
- 在本地页面中抓取 OpenID
- 配置每日自动签到
- 记录自动签到结果和执行日志

## 2. 项目主要功能

### 2.1 手动签到

可以在本地页面中点击按钮立即执行签到，适合首次验证配置、排查问题或临时补签。

### 2.2 多账号签到

`.env` 中的 `openid` 支持使用英文逗号分隔多个值，程序会按顺序逐个执行。

示例：

```env
openid=openid_1,openid_2,openid_3
```

### 2.3 OpenID 抓取

项目提供了本地抓取能力，会优先尝试使用 `mitmproxy`，如果不可用，则回退到 `WMPFDebugger`。

### 2.4 自动签到

可以在本地页面中设置：

- 每天
- 工作日
- 指定日期

保存后，项目会在 Windows 中创建本地计划任务，按设定时间自动触发签到程序。

### 2.5 自动补跑与去重

当前项目已经补充了以下机制：

- 同一天“成功签到过”后，不再重复签到
- 如果当天只是执行失败，后续自动触发仍可继续补跑
- Windows 计划任务支持错过后尽快执行
- Windows 计划任务支持失败后自动重试

## 3. 运行方式

## 3.1 安装依赖

在项目根目录执行：

```bash
npm install
```

如果你习惯使用 Yarn，也可以继续使用：

```bash
yarn
```

## 3.2 配置环境变量

在项目根目录创建 `.env` 文件，并写入：

```env
openid=你的openid
```

如果有多个账号：

```env
openid=openid_1,openid_2
```

## 3.3 命令行脚本运行

手动执行签到：

```bash
npm run script
```

执行自动签到调度入口：

```bash
npm run script:schedule-runner
```

## 3.4 本地页面运行

启动后端与前端开发环境：

```bash
npm run dev
```

启动后：

- 后端默认运行在 `http://127.0.0.1:3001`
- 前端由 `web` 目录中的 Vite 提供开发服务

你可以在页面中完成：

- 保存 OpenID
- 抓取 OpenID
- 手动签到
- 保存自动签到配置
- 查看最近一次自动签到结果

## 4. 自动签到是怎么工作的

自动签到的执行链路如下：

1. 在页面中保存自动签到配置
2. 后端把配置写入 `.codex-tools/schedule.json`
3. 后端调用 Windows 计划任务创建本地定时任务
4. 到达触发时间后，系统调用 `run-csuft-unsafe-dorm.cmd`
5. `run-csuft-unsafe-dorm.cmd` 再调用 `run-csuft-unsafe-dorm.ps1`
6. PowerShell 脚本执行 `npm run script:schedule-runner`
7. 程序判断今天是否需要执行，以及今天是否已经成功签到
8. 执行签到，并写回结果与日志

## 5. 日志说明

项目中目前有两类与自动签到相关的日志。

### 5.1 计划任务总日志

文件位置：

`scheduled-task.log`

用途：

- 记录计划任务每次触发时的标准输出和错误输出
- 适合排查计划任务有没有被系统唤起

编码：

- 已调整为 UTF-8，便于直接查看

### 5.2 自动签到结果日志

文件夹位置：

`日志`

规则：

- 程序触发自动签到时先检查是否存在 `日志` 文件夹
- 如果不存在，就自动创建
- 每次执行都会生成一个独立日志文件

命名格式：

`年-月-日-时-分-秒+结果.log`

示例：

- `2026-05-08-21-28-26成功.log`
- `2026-05-08-21-29-28跳过.log`
- `2026-05-08-21-30-10失败.log`

日志内容会记录：

- 触发时间
- 执行过程
- 成功、失败或跳过结果
- 日志生成时间

## 6. 常见使用建议

### 6.1 首次使用建议

建议首次按下面顺序操作：

1. 安装依赖
2. 抓取并保存 OpenID
3. 手动执行一次签到
4. 确认页面返回正常
5. 再启用自动签到

### 6.2 自动签到时间建议

建议把自动签到时间设置在签到窗口开始之后，并预留一定余量，不要压在最后几分钟。

### 6.3 多账号建议

如果配置了多个账号，程序会顺序处理。账号越多，整体执行时间越长，设置自动签到时间时要预留足够窗口。

## 7. 排查思路

如果自动签到没有按预期工作，可以优先检查：

1. `.env` 中的 `openid` 是否有效
2. 本地页面能否手动签到成功
3. `scheduled-task.log` 是否有触发记录
4. `日志` 文件夹中是否生成了对应时间的日志文件
5. `.codex-tools/schedule.json` 中的最近结果是否为成功
6. Windows 计划任务是否仍存在

## 8. 目录参考

几个关键文件如下：

- `src/server.ts`：本地服务、接口、计划任务管理
- `src/scheduler.ts`：自动签到配置读写与日期规则判断
- `src/scripts/schedule-runner.ts`：自动签到入口
- `run-csuft-unsafe-dorm.cmd`：Windows 计划任务命令入口
- `run-csuft-unsafe-dorm.ps1`：Windows 自动签到执行脚本
- `scheduled-task.log`：计划任务总日志
- `日志/`：每次自动签到的独立中文日志目录

## 9. 一句话理解

这个项目就是一个“本地运行、OpenID 认证、可手动也可定时自动执行、支持日志追踪和失败补跑”的平安打卡工具。
